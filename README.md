# ai-app-panel

**将 AI Agent 创建的应用从代码成果变成可访问、可管理、可运营的服务。** ai-app-panel 是一套自托管的 AI 应用门户与运行平台：Agent 可按 AWPK 规范打包应用，用户上传后即可安装和发布 HTML、前端工具及 Python 应用；平台提供统一访问入口、应用可见范围与登录控制，并通过沙箱运行 Python 应用。对于已有服务，也可通过应用网关统一接入。平台还内置 OpenAI 兼容的 LLM 网关，支持多上游路由、应用与用户用量归因，以及会员、积分和 Token 额度管理，帮助个人或团队在自有环境中部署、分享并运营 AI 应用。

```
用户 ──HTTPS──▶ ai-app-panel（自动证书，监听端口）
                  ├─ 门户 UI ──▶ 应用卡片墙 / 主题 / 品牌 / 备案
                  ├─ 用户中心 ──▶ 个人信息 / 财务 / 安全 / 注销
                  ├─ 应用网关 ──▶ 路径反代 ──▶ 127.0.0.1:8001 (app A)
                  │             ──▶ 127.0.0.1:8002 (app B)   [HTTP + WS/SSE]
                  ├─ LLM 网关 ──▶ OpenAI 兼容中转 ──▶ 阿里云/智谱/火山/vLLM…
                  └─ 计费 ──▶ 会员权益 + token 额度池
```

## 开发

```bash
pnpm install
pnpm dev          # server: http://localhost:8080 · web: http://localhost:5173
pnpm skills:sync  # 生成 AWPK .skill/.zip/.md 并同步到 apps/server/assets
pnpm build        # 自动同步 skill 后构建
pnpm test          # 单元/集成测试（服务端 24 个测试文件 233 个用例）
pnpm test:e2e     # Playwright 端到端（自动起真实服务 + mock 上游）
pnpm typecheck    # 全部类型检查
```

要求 Node ≥ 22。开发服务器、服务端测试与 E2E 均要求可访问的 PostgreSQL；通过 `DATABASE_URL`（测试可用 `TEST_DATABASE_URL` 或专用的 `E2E_DATABASE_URL`）指定连接串。测试会创建并删除隔离 schema，因此数据库用户需要 `CREATE SCHEMA` 权限。E2E 不使用 SQLite 文件，运行后会删除自己的 schema。

AWPK Agent skill 的源文件是 `docs/app-develop.skill-v0.3.md`。修改后执行 `pnpm skills:sync`，生成 `.skill`、`.zip` 和 `.md` 三种下载格式并同步到 `apps/server/assets`，供「操作导航」下载；压缩包内的 `SKILL.md` 位于 ZIP 根目录，避免部分 Agent 无法识别。

本地账号新密码需为 8-128 位，并至少包含大写字母、小写字母和数字；注册、找回密码、修改密码及管理员手动设置初始密码均执行此规则。

Docker 部署默认包含 PostgreSQL：

```bash
cd deploy/docker
cp .env.example .env       # 修改 POSTGRES_PASSWORD，使用长随机字母数字密码
docker compose up -d --build
```

全新部署使用独立 PostgreSQL 数据库 `ai_app_panel` 和 Docker 卷 `ai-app-panel-postgres-data`、`ai-app-panel-data`。门户文件（证书、密钥、应用包、站点 Logo 等）保存在 `ai-app-panel-data`；Logo 图片写入 `/data/admin/site-logo/`，其 `/uploads/sitelogo/...` 地址由服务端映射提供，不需要单独挂载 `/uploads`。旧项目数据库、表结构及数据不迁移、不导入；请使用全新数据库和本项目新卷。容器启动时自动应用 `drizzle-pg/` 中的初始迁移。

原生运行包与飞牛 FPK 不内置数据库服务，需另行提供 PostgreSQL 17 并配置 `DATABASE_URL`（FPK 由安装向导收集连接串）。平台业务数据统一存于 PostgreSQL；托管应用可使用各自独立的 `app.sqlite` 保存应用自身状态。

“我的应用”分为“我自己的”“已共享的”和“站内共享”。已共享列表用于直接访问公开应用；站内共享应用不能直接打开，只能克隆到自己的账号。克隆复制应用文件与环境变量，固定为“仅自己”可见，并占用当前权益的可克隆名额；删除克隆后名额自动恢复。应用卡片内容垂直居中且上下留白一致，首页「发现应用」中不单独显示“用户提交”分类标题；可访问的应用卡片使用 3D 悬浮效果及访问二维码。

个人中心「应用管理」中的已创建应用支持点击名称查看双列详情，点击「设置」可点击图标上传并持久化到应用私有目录、编辑名称/描述/可见范围，并在同一圆角弹窗配置环境变量；无环境变量时显示简洁空状态图；名称为 `MODEL`、`OCR_MODEL` 或 `MODEL_NAME` 等模型变量仅显示可搜索模型下拉框，从管理后台已启用的模型路由中选择，不显示应用专属描述或重复文本框；新 LLM 应用统一声明必填 `MODEL`；唯一的「保存设置」按钮会一并保存基础设置和环境变量；上传 AWPK 后，在上传按钮下显示不确定进度条直到校验/依赖安装结束，过程中禁用重复上传；删除操作保留独立按钮。


## 核心能力（当前实现）

- **认证与资料布局**：登录与注册页使用相同的图文分栏比例，注册信息在右侧垂直居中；个人资料表格不显示边框，昵称输入框占信息列宽度的一半，头像悬停提示适配当前主题。
- **环境变量配置**：应用设置以“变量名、变量值、变量说明”三列表格展示；必填值以红色边框和“必填”占位提示标识，不使用星号或额外说明文案。
- **个人中心 Dashboard**：固定可折叠左侧导航，按「应用」「账户和安全」「权益中心」分组提供六个二级入口，导航项悬浮时有高亮反馈；「应用管理」标题说明后提供操作指南入口；浅色主题下内容、侧栏和卡片均使用白色背景，深色主题下各板块、表格分页和弹窗统一使用深色调；基础资料以无边框二维表格呈现，支持上传头像和修改昵称，用户名、邮箱及角色只读；已创建应用列表紧凑显示、每页十项，手机屏幕可横向滚动查看完整列；隐藏门户页眉，品牌与用户入口分别置于侧栏顶部和底部，每次只展示一个带标题和说明的内容面板。
- **全站字体**：门户、认证页、操作导航、个人中心及管理后台统一使用系统无衬线字体；代码与密钥等需要对齐的内容保留等宽字体。
- **管理后台总览**：与个人中心共用主题、侧栏和卡片布局；设置分区通过左侧导航访问，不再显示首次配置向导。总览提供 CPU、内存、网络带宽水位图，注册用户/应用总数及近 30 天 Token 累计进度，以及有效订阅计划分布饼图。

- **应用网关**：配置「本站域名」后，应用使用 `<应用 ID>.<本站域名>` 独立 origin，可使用自己的 localStorage 和 Cookie；未配置域名时所有应用使用门户同源入口（用户上传应用仍由 opaque-origin iframe 沙箱隔离，不暴露服务端内部端口）。缺失或空 Host 会安全回落到门户路由，不触发子域名解析异常。平台会话 Cookie 不转发给应用、应用 Cookie 限定为当前主机；HTTP 下将应用 Cookie 的 `SameSite=None` 调整为 `Lax`，HTTPS 下保留 `SameSite=None` 并添加 `Secure`。生产需配置通配 DNS 与 `*.<本站域名>` 证书；证书面板使用 Cloudflare DNS-01 签发通配符证书。路径反代仍支持上游应用（HTML 改写 / `<base>` / fetch+XHR+script 猴补丁 / 路径穿越防御 / SSE 零缓冲）；管理员可在应用管理查看进程生命周期、HTTP 错误/超时和慢请求运行事件（不记录请求正文或凭据）；**WebSocket 透传**（HTTP+HTTPS 双通道），passUser 签名身份注入（X-AAP-Identity）
- **门户托管应用**：简单 HTML 页直接粘贴接入；上传 AWPK（ZIP 容器，必须 `.awpk` 扩展名，包含 `manifest.json`）后自动校验并安装；更新同一应用时必须递增 `manifest.version`，至少增加 PATCH，不能重复使用旧版本或重置为 `1.0.0`；Python 依赖安装期间界面提示等待状态，容器日志记录开始、定时进度、完成或失败；不接受旧 `.asp-app` 或通用 `.zip` 文件。包上传即自动签发网关凭据（加密保管，运行时注入；未声明 `llm` 能力的包凭据仅用于出站代理，LLM 调用在网关侧按能力声明闸拒绝）；manifest `env` 声明环境变量/机密（每包最多 16 项、值最多 8,192 字符），归属者或管理员在门户填值、密钥加密存储（只写不读），沙箱启动时注入进程环境变量。Python 包通过 `aap.*` 使用隔离 SQLite、默认 10 MiB 文件存储和仅 GET 的白名单 HTTP 代理；当前没有 per-app CPU/内存硬限额或 SQLite 硬配额，能力清单、准确限制与 Agent 禁止事项见 [`docs/app-develop.skill-v0.3.md`](docs/app-develop.skill-v0.3.md)；个人中心应用列表使用图标展示数据库、大模型、网络白名单和存储能力，并按列显示安装日期、包大小、版本及提供设置/删除操作，环境变量弹窗与个人中心主题保持一致
- **应用数量权益**：权益套餐分别限制用户可创建的托管应用数量与同时持有的站内克隆数；克隆不占创建额度，副本固定为仅自己可见，删除即归还克隆额度。可创建应用数量为 0 的权益展示为“—”；同名更新不额外占用创建名额。
- **公开发布积分奖励**：后台可为每个用户分组设置公开发布奖励；用户首次公开自己的应用时按所属分组获得一次积分，删除已获奖励的应用时扣回（余额最低为 0），重复发布不会重复获得奖励。
- **LLM 网关**：OpenAI 兼容 `/v1/chat/completions`（流式）+ `/v1/models`；多上游按优先级+权重 failover；网关凭据（SHA-256 存储/可吊销/限流），**能力声明闸**对 `/v1` 直连与沙箱代理双侧强制（manifest 未声明 `llm` 一并 403）；用户级+应用级计量（append-only 账本）、余额预检 402、预估事后校正；沙箱调用支持平台默认模型与生成上限（`LLM_DEFAULT_MODEL` / `LLM_SANDBOX_MAX_TOKENS`，0=不限）、上游连通性一键测试；**无归因调用默认拒绝**（`LLM_UNATTRIBUTED_POLICY` 可放行）
- **门户首页**：首屏以 `apps/server/assets/home-background.png` 为背景，展示「使用 [站点名称] 零代码创作个人软件」及平台简介，文案中的站点名称、页眉、应用列表和页脚共享统一配置，页面内容与背景卡片左右边界对齐；「现在开始」未登录时进入登录页、已登录时进入个人中心，「操作指南」直达指南页面，搜索框位于应用列表；页眉固定在顶部，背景保持浅色并使用居中内容宽度；「发现应用」、权益、FAQ 与登录按钮使用等间距排列；发现应用卡片垂直居中显示内容并保持上下留白一致，“用户提交”分类不显示独立小标题，卡片带轻量 3D 阴影与悬浮效果，悬停时右侧以抽屉动效展示访问二维码，点击卡片直接打开应用；仅首页、登录和注册页面显示页脚；其它显示门户页眉的页面保持磨砂透明背景；登录/注册采用图文分栏布局，注册表单紧凑排布并在较矮视口内独立滚动，提供服务条款与可接受使用政策
- **HTTPS 证书**：证书管理通过 Cloudflare DNS-01 自动签发/续期根域名及通配符证书，并展示当前证书颁发者、覆盖域名、有效期和指纹；失败信息包含签发阶段及底层网络错误；ACME 请求优先使用 IPv4 以兼容无 IPv6 出站路由的服务器；Cloudflare API Token 加密保存，建议仅授予目标 Zone 的 DNS:Edit 权限
- **站点品牌设置**：后台站点设置可直接上传 PNG/JPEG/GIF/WebP Logo（最大 5 MB），图片持久化到数据卷 `admin/site-logo` 目录；保存后站点名称同步更新浏览器页面标题，Logo 同步显示为浏览器标签页图标及门户品牌；可配置页脚文案、版权声明与备案号，首页页脚居中展示管理员邮箱作为站内违法和不良信息举报邮箱，点击可直接发送邮件
- **账号与安全**：默认开放本地账号注册，管理员可随时在邮箱验证码与阿里云 Dypnsapi 手机短信验证码间切换；短信注册限中国大陆手机号，使用加密保存的 AccessKey 和管理员配置的已审核签名/模板，登录仍使用用户名和密码。邮件注册及找回/绑定邮箱验证码支持 SMTP/Resend/日志兜底；手机号注册账号可在个人中心验证新邮箱完成绑定，所有换绑发码后目标地址会锁定以避免校验地址与收码地址不一致，手机号换绑还需步升认证和阿里云短信验证。另可启用 Turnstile；平台会话 Cookie 默认使用 host-only 域，配置「本站域名」后才扩大到该域，以兼容实际部署域名并避免 localhost 域 Cookie 导致会话丢失。每个账号自动拥有唯一邀请码，注册时可选填写他人邀请码，成功邀请默认奖励 100 积分；后台可查看邀请码属主和注册人数并停用奖励（停用不阻止注册），用户菜单提供含邀请码二维码的「账号电子身份卡」。新账号自动分配预置头像并按策略赠送初始积分，个人中心支持上传自定义头像；初始管理员获得 99,999,999 积分、普通新用户在有可用权益包时选择套餐（零价立即生效、积分足额即时兑换、人民币/美元创建人工确认订单；无可用套餐时以未订阅状态进入个人中心）、右上角头像昵称入口展示当前实际权益及等级图标、账号资料与浅色/深色/跟随系统选择（通过浏览器 cookie 保持选择，仅影响个人中心和「我的应用」）、导航直达个人中心和独立「我的应用」卡片墙、登录后进入个人中心、MFA（TOTP+Passkey，绑定新因子需步升）、OIDC 单点登录（PKCE）、登录防爆破（IP+账号双维度）+IP 封禁累犯倍增+PoW、步升认证（登录即授窗口）、审计日志、敏感配置 AES-GCM 落盘、HTTPS 启用即挂 HSTS
- **订阅与计费**：个人中心「我的权益」展示权益用途、实际额度与历史订阅；「获取权益」支持查看方案、积分兑换及兑换码获取；人民币/美元/积分三种套餐计价（人民币和美元沿用人工确认，积分与 LLM Token 独立并在事务内扣减、立即开通）；更高等级权益订阅后立即生效，同等级订阅从当前权益到期时间顺延，较低等级须等当前权益到期后才能订阅；管理员可编辑已发布套餐，应用创建/克隆额度调整立即作用于有效订阅者，Token 赠额、价格和有效期调整用于后续开通或续订；订阅账单可按套餐展示管理员配置的外部兑换码链接、注册赠分策略、等级 0–5 套餐配置及等级图标、可配置的 Token 额度获取与运营面板（套餐/订单/卡券码/排行/成本毛利）；卡券批次和列表查询兼容 PostgreSQL 分组与主键排序规则
- **可见性模型**：公开 / 站内共享（不可直接访问、可克隆）/ 仅自己（用户自建与克隆应用默认私有，门户对他人隐藏）
- **统一页面元素**：兼容路径模式下的托管/代理应用可注入右下角站点名称入口（名称使用后台站点配置）；独立应用 origin 不注入门户页面脚本，避免把门户功能暴露给用户应用
